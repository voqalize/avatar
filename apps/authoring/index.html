Avatar — the workshop

For drawing avatars and making them move. Every page here renders through the same code that ships, so what you see is what a caller gets — and the rig is judged by eye, which is why these show you a face rather than a number. Nothing needs a build step: edit a file in src/, reload, look.

Serve this directory's parent with python3 apps/authoring/serve.py 8777 and open localhost:8777/authoring/. Not python3 -m http.server — it lets the browser cache modules you have edited, which has cost three debugging sessions here, one of them producing an error message that was simply untrue.

Start here when a rig is new or broken

  • professional-compare.html

    The four professional variants side by side in their live rest pose, with a second render at the 130 px production width. This is the visual approval sheet; Studio remains the published-interface check.

  • rig-check.html

    Every registered avatar side by side through live createAvatar instances — same command, same moment, so any difference on screen is a difference in the avatar and never in the driving. Console: await sweep() is the conformance test, pose({…}) holds a raw vector on all rigs.

  • contact-sheet.html ?face=NAME

    Static poses for one avatar — every viseme, emotion, gaze target and channel extreme, straight from apply(p) with no mixer and no clock. Includes the mouth-detail row, where letter collisions are visible and on the full-head row they are not.

  • torso-check.html ?face=NAME

    Shoulder, lean, trunk-turn and head-pose combinations. Separate from the contact sheet because these channels only fail together, and this is where a rig leaks background from behind the shirt if it is going to. The rows marked (worst) are the failure envelope, well past anything the live mixer sends.

  • control-plane.html

    The peep control-plane study — the rig stripped to only the geometry that apply(p) actually writes, so what a channel moves is visible without the rest of the drawing on top of it. The companion of authoring-a-face.md's channel walk-through.

Motion and timing

  • clip-strip.html ?clip=NAME&n=32&crop=x,y,w,h

    A gesture clip as a filmstrip instead of a playback. Steps a real ClipPlayer in 1/60s ticks with the mixer's own smoothing, so the phase relationships between shoulders, brows and mouth are legible in a still. Gesture channels only — an interjection's cue track is not applied here, so a shut mouth in the strip is the harness, not the rig.

  • body-lab.html ?face=NAME&state=LISTENING&seed=7&w=440&talk=0&user=0

    The rig driven by hand: seeded RNG installed before the modules load, no requestAnimationFrame, and window.stepTo(t) walking the mixer to an absolute simulated time in 1/60s ticks. Same seed, same t, same pixels — which is the only reason a change to the liveness layer can be measured at all. Not a page to look at; it is the driver for node apps/authoring/tools/motion.mjs, which reports how far the body actually travels in delivered pixels. &gesture=GESTURE_GREET&at=0.4&side=1 fires a hand gesture at an absolute sim time, which is how a frame-edge hand gets filmstripped or screenshotted at peak extension.

  • expression-lab.html

    Clip and beat authoring against real audio.

  • lipsync-eval.html

    Cue tracks A/B, sphinx vs phonetic, scored blind.

  • lipsync-review.html

    Ten clips with their audio, both legs of the shipping library, text shown. The one next door hides it to grade; this one shows everything to diagnose — swap accurate/predicted mid-sentence against the same voice.

  • pipecat-lifecycle-lab.html

    Drives the real client adapter from a Pipecat-shaped event stream. Use its scenario traces to inspect lifecycle projection, speech safety and the boundary between SDK facts and explicit server actions.

Drive one by hand

  • workbench.html

    One avatar and every control there is: states, emotions, gaze, the interjections, the hand gestures, text you type turned into visemes, and the raw parameter sliders underneath all of it. This is the page to open when the question is what does it look like when… rather than is this rig correct.

Not here

  • apps/server/

    A real call — your microphone, a real pipecat process, no API key. The only place lipsync can actually be judged, because only there do the two viseme legs interleave under a live generator. Run cd py && uv run --group server python ../server/server.py first; nothing here starts it for you.

  • apps/studio/

    The IDE for the published interface — the options a product developer passes to createAvatar, and the wire, on the same live call. It knows nothing about rigs. pnpm run studio:dev.
